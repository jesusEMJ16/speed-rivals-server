# Speed Rivals online v2

One Node.js 22+ instance owns the rooms, race clocks, guest identities, and online ranking. Run `npm ci`, then `npm start`. Run `npm test` for real local WebSocket integration tests. Tests use temporary files or injected storage and never contact the published backend or real Redis.

## Deployment configuration

- Set `NODE_ENV=production`, and use the hosting platform's `PORT`.
- Configure the existing `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`, **or** set `SR_DATA_FILE` to an absolute file path on a mounted persistent disk. Upstash takes precedence. Never store secrets in the web client, Git, or shared URLs.
- The new single-document storage key defaults to `sr:v2:state`. Override with `SR_STORAGE_KEY` only for an isolated season/environment. Historical `sr:rank`, `sr:prof`, `rank.json`, and `profiles.json` are not read into the official v2 ranking and are never modified. Reserved historical Redis keys cannot be selected for v2 writes.
- Files use write, fsync, and atomic rename. Redis saves the whole v2 document with one SET. Identities and completed results are committed before acknowledgement. Guest bearer tokens are hashed in storage; the client stores its own secret token.
- Production readiness fails closed without storage, on invalid/corrupt data, or after a failed write. `/health` reports process liveness; `/ready` returns 200 only when storage has loaded and passed a write. Use `/ready` for deployment readiness and `/health` for liveness. Initial storage failure requires restoring configuration/storage and restarting. Failed match commits retry every 500 ms; no saved result is broadcast until persistence succeeds.
- Use **one instance and one writer**. Do not enable horizontal scaling or concurrent rolling instances against the same key: matchmaking is in memory and this implementation does not provide distributed locking. Allow active races to drain before stopping/redeploying. An abrupt process loss cancels unfinished races without awarding points; committed results and profiles survive restart.
- Configure HTTPS/WSS on the hosting platform. Itch.io and Android clients must use the same public WSS endpoint and protocol version 2.
- `/invite/ABC123` displays the room code and links to this server's bundled game at `/play/?room=ABC123` by default. The parent client build supplies `public/index.html`, `public/privacy.html`, and nine font license files. Only those eleven explicit filenames are served under `/play/`; missing files return 404, other paths cannot access the filesystem, and only GET is accepted. Game pages permit embedding and keep the existing standalone client's inline assets. Optional `SR_WEB_PLAY_URL` overrides the invitation link with a trusted, directly playable external URL; `?room=ABC123` (or `&room=ABC123`) is appended. The code works manually on either platform. Android App Links require the app's real application ID, signing certificate, and a later verified association deployment; none are invented here.
- The `.env.example` documents environment values. Node does not automatically read `.env`; configure environment variables through the host or your launcher.

## Protocol

All frames are JSON with `type`. Send `hello {protocol:2, token?, name}` and await `welcome {protocol:2,id,token,profile,serverTime}` before actions. Guest identity follows the token, not the display name. Names support Unicode, max 24 code points. Invalid saved tokens return `INVALID_TOKEN`; do not silently erase an existing token on a temporary connection error.

Lobby commands: `joinpub {mode}`, `create {roomName,priv,mode}`, `joinroom {code}`, `list`, `leave`, `setmode {mode}`, `setpriv {priv}`, `startRace`. Modes: `normal`, `subita`, `supervivencia`. Automatic queues start with exactly nine connected human identities; a tenth human gets a distinct queue, and modes never mix. Manual rooms need 2–9 connected people and host permission to start. Private rooms do not appear in `rooms` lists. Host transfers when the current host leaves or disconnects.

`loadout {car,llanta,gadget,abil}` updates only the authenticated player's display metadata while attached to a room, including countdown and spectating. Values must be null or lowercase ASCII identifier strings (letters, digits, underscore), 1–32 characters. Only these four keys are copied and exposed in room player rows; metadata grants no inventory, physics changes, CP, or changes to other players.

Join acknowledgement is `created/joined {code,queue}`, then `room {id,code,queue,racing,mode,host,manual,priv,roomName,p,matchId?,seed?,startAt?,endsAt?,serverTime,spectating}`. `id` identifies the recipient. `p` contains public `id,name,col,d,lane,alive,connected,cp` for every retained entrant. A disconnect reserves the lobby slot for 15 seconds. During races, distance freezes immediately and the entrant is eliminated after that grace; standings retain the entrant. Reconnect during a race is spectating and cannot resurrect local physics. Reconnect after finish replays the last saved `end`, even across restart; clients deduplicate match IDs.

`start {matchId,seed,mode,startAt,endsAt,serverTime}` gives one shared 2450 ms countdown followed by a 120000 ms race. Use the server time offset, not local wall-clock assumptions. States are `st {matchId,seq,d,lane,alive}`. **Use one increasing sequence across all `st`, `pickup`, and `atk` messages per match.** Canonical distance is independent of the viewport, and meters are `d * .03`. Server bounds distance to 5000 canonical units/sec plus a 240-unit initial allowance and a bounded burst budget. Reverse distances, impossible lanes, stale sequences, wrong matches, pre-start/expired updates, and resurrection are rejected. Client physics remain client-reported: these are plausibility checks, not complete simulation-based anti-cheat.

Attack items: `oil`, `cones` (legacy `cone` accepted), `rayo`, `emp`, `gancho`, `prisa`, in normal mode. `pickup {matchId,seq,kind}` grants one inventory slot, minimum 3500 ms between accepted pickups. `inventory {matchId,item}` confirms it. `atk {matchId,seq,kind}` consumes the matching slot, minimum 750 ms between launches, and acknowledges `item:null`. The server chooses the nearest valid live connected opponent; rayo/EMP target all valid opponents. Targets receive `atk {matchId,eventId,kind,from}` with a server-generated event ID and authenticated sender. Item collection itself is plausibility-limited, not physically proven.

When all racers are eliminated or the deadline expires, the server orders entrants by distance with public ID as stable tiebreaker. CP by position is `[40,25,15,8,0,-8,-15,-22,-30]`, with totals floored at zero. All profiles are updated together; online `bestVs` is meters. `end {matchId,rank:[{id,name,d,cpDelta,cpTotal}],roomRank,serverTime,saved:true}` is emitted only after the entire result is durable. A player who leaves an unfinished race remains in its standings and cannot enter another race until the result closes.

`getstats` returns `profiles {profiles,source:'online',season:'v2',updatedAt}` with public `id,name,cp,bestVs,wins,races`. `getrank` returns the equivalent array under `rank`. `stats {name}` changes only the name; client CP/best-score fields are ignored. `score` is rejected. Errors are `err {code,msg}` (including `INVALID_VERSION`, `INVALID_TOKEN`, `AUTH_REQUIRED`, `ROOM_NOT_FOUND`, `ROOM_FULL`, `RACE_ACTIVE`, `NOT_HOST`, `RATE_LIMIT`, `INVALID_STATE`, `STORAGE_UNAVAILABLE`). `ping {sentAt}` returns `pong {sentAt,serverTime}`; WebSocket protocol ping/pong detects dead connections.

## Operational limits

Profiles and completed match IDs are retained in the v2 document without pruning, to preserve exactly-once results. Monitor document size and storage limits as usage grows; archive/migrate with an explicit retention design before those limits are approached. Guest tokens are device-local; no account recovery or automatic cross-device identity linking is provided. Deploy protocol v2 together with the updated web and Android clients; previous clients are incompatible.

Programmatic local integration: `createServer({port:0,host:'127.0.0.1',dataFile,redis:null})` returns `{wss,rooms,httpServer,address,ready,close}`. Await `ready` before connecting. Tests may inject a `{load,save}` storage adapter and short `countdownMs`, `durationMs`, `tickMs`, or `disconnectGraceMs` values. `close()` is idempotent.
